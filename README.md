# 謎解き制作システム

`index.html`を画面として、`app.py`を単語探索・規則適用・AI連携・Webサーバーとして動かす、文字変化型の謎解き制作システムです。

## 概要

単語辞書から候補を選び、単語同士に共通する文字操作や音の変化を探索します。同じ規則で成立する単語ペアを3組そろえ、次のような謎を生成します。

```text
すいか → いか
みかん → かん
さくら → ？
```

この例では、2つの例題から「先頭の1文字を削除する」という規則を推測し、最後の答えとして「くら」を導きます。

AI APIキーが設定されている場合は、探索済みのペアからAIが規則を1つ選び、問題文・ヒント・解説を生成します。APIキーがない場合も、同じ探索結果を使った自動生成で動作します。

## システムの方法（①〜⑧）

### ① 辞書・単語リストを準備する

`unidic_candidates.js`に、精査済みの候補単語をJavaScript配列として保持します。現在の候補数は12,600語です。`app.py`にも同じ単語リストを内蔵しています。

候補の作成では、UniDicの`lex.csv`を元にして、次の条件を適用します。

- 名詞は普通名詞、副詞は候補にする
- 固有名詞・人名・接尾辞などを除外する
- 元の読みが2〜4文字の語に限定する
- 古い仮名遣いや不自然な表記を除外する
- 和語は標準的なひらがな表記、外来語は標準的なカタカナ表記にする
- 不適切語・卑語・薬物関連語・スラングなどを除外する
- 除外した語の分は頻度順位の次候補から補充する

ただし、辞書の頻度順位は「小学生が知っている順」そのものではありません。そのため、候補一覧を画面で確認し、採用・不採用を最終的に人が判断できるようにしています。

### ② 候補単語を精査する

画面上部の「単語候補一覧」で単語を検索し、使いたい単語の「採用」ボタンを押します。採用した単語はブラウザの`localStorage`に保存され、次回も維持されます。

採用単語だけが、通常のAI生成と規則探索の対象になります。

### ③ 入力条件を指定する

画面の入力欄では、次の4項目を指定できます。

1. `A → ？（新単語から）`：変化後の単語を指定する
2. `？ → B（元単語から）`：変化前の単語を指定する
3. 規則：自動、または特定の規則を指定する
4. テーマ：指定なし、ファンタジー、海、宇宙、未来

例えば、変化前を「すいか」、変化後を「いか」、規則を「先頭1文字削除」と指定すると、その条件に一致するペアを探索します。未入力の項目は自動選択になります。

### ④ 規則を全候補へ適用し、ペアを探索する

各単語に対して、下記の規則を順番に適用します。変換後の文字列が同じ辞書に存在する場合だけ、成立する単語ペアとして保存します。

同じ単語の同じ規則による重複は除外します。また、問題に使う場合は同じ規則のペアを3組以上持つグループだけを候補にします。異なる規則のペアを混ぜて1問にすることはありません。

#### 文字操作

- **先頭1文字削除**：`すいか → いか`
- **末尾1文字削除**：`りんご → りん`
- **中間1文字削除**：先頭と末尾を残し、中央の各位置を1文字ずつ削除します
- **先頭1文字追加**：辞書で使用する仮名を先頭に1文字追加します
- **末尾1文字追加**：仮名を末尾に1文字追加します
- **中間1文字追加**：先頭・末尾以外の各位置に仮名を1文字追加します
- **先頭文字置換**：先頭の文字だけを別の仮名に置き換えます
- **末尾文字置換**：末尾の文字だけを別の仮名に置き換えます
- **中間文字置換**：中央の各位置を別の仮名に置き換えます

追加・削除は、候補単語の長さが2〜4文字の範囲に収まるようにしています。

#### 音の変化

- **濁点・清音変換**：`か↔が`、`さ↔ざ`、`た↔だ`、`は↔ば`など、濁点の有無を切り替えます
- **半濁点変換**：`は↔ぱ`、`ば↔ぱ`など、半濁点を含む変化を試します
- **母音変換**：同じ位置の母音を、`あ・い・う・え・お`の別の母音に置き換えます
- **子音スライド**：同じ仮名行の中で子音を変更します。例えば、か行・さ行・た行などのグループ内で変換します

変換後の語が辞書に存在しない場合、その候補は採用しません。

#### 配置の変化

- **逆読み**：文字列を完全に逆順にします
- **並び替え**：文字の順番を全通り試します。ただし、元の並びと単純な逆読みは重複するため除外します

例えば「すいか」では、並び替えとして「すかい」「いすか」「いかす」「かすい」などを調べ、辞書にある一般的な単語だけを残します。

### ⑤ AIが規則・問題・ヒントを生成する

成立したペアを規則ごとにグループ化し、3組以上ある規則だけをAIに渡します。AIには次の条件を指定しています。

- 1問につき1つの規則だけを使う
- 同じ規則のペアを3組使う
- 1組目と2組目を例題、3組目を問題にする
- ヒントは文字数、位置、変化している規則の順にする
- テーマが指定された場合は、問題文や表現に反映する
- JSON形式で返す

AIが返したペアが実際の探索結果に存在するか、問題が3行か、ヒントが3個あるかを`app.py`で検証します。検証に失敗したAI出力はそのまま表示しません。

APIキーがない場合は、同じ規則グループから自動的に3組を選び、固定形式のヒントと解説を生成します。

### ⑥ 判定結果を計算する

問題生成時に、元単語と答えの編集距離を計算します。編集距離は、文字の追加・削除・置換が何回必要かを表します。

```text
スコア = (1 - 編集距離 / 長い方の単語の文字数) × 100
```

画面ではスコアを点数で表示し、50点以上を「採用候補」、50点未満を「除外候補」としています。これは生成されたペアが文字列としてどの程度近いかを見る補助的な指標です。正解・不正解の判定は、入力された答えと正解文字列が一致するかで行います。

### ⑦ 問題・ヒント・解説を表示する

生成された問題は、例題2行と未回答の問題1行で表示します。問題欄は改行を保持するため、3行の謎として表示されます。

ヒントは`details`形式で折りたたまれており、必要なヒントだけ開けます。正解するまでは答えと解説を隠し、正解後に表示します。

### ⑧ 回答・得点・次の問題を処理する

回答欄に答えを入力して「回答する」を押すか、Enterキーを押します。

- 正解の場合：正解メッセージ、答え、解説を表示し、正解数を1増やす
- 不正解の場合：答えを表示せず、再挑戦を促す
- 複数問題がある場合：「次の問題へ」で次の問題に進む

## 使い方

### 実行方法

このプロジェクトのフォルダをターミナルで開き、次を実行します。

```powershell
py app.py
```

起動後、ブラウザで次のURLを開きます。

```text
http://localhost:8000/
```

停止するときは、サーバーを起動しているターミナルで`Ctrl+C`を押します。

### AIを使う場合

PowerShellでAPIキーを環境変数に設定してから起動します。

```powershell
$env:GEMINI_API_KEY="自分のGemini APIキー"
py app.py
```

モデルを変更する場合は、任意で次を設定できます。

```powershell
$env:GEMINI_MODEL="gemini-2.0-flash"
```

APIキーが設定されていない場合は、自動生成に切り替わります。APIキーを`README.md`やGitHubへ直接書き込まないでください。

### 操作方法

1. 候補一覧から単語を検索する
2. 問題に使う単語の「採用」を押す
3. 採用単語を3語以上用意する
4. 「AIで問題を作る」を押す
5. 必要に応じて、③の入力欄で元単語・新単語・規則・テーマを指定する
6. 表示された3行の問題を解く
7. 必要なヒントを開く
8. 答えを入力して判定する

## 工夫した点

### 同じ規則だけで1問を構成する

「先頭文字削除」「末尾文字削除」「中間文字追加」を混ぜると、例題から規則を推測できません。そのため、規則ごとにペアをまとめ、同一グループから3組を選ぶようにしています。

### AIに自由に答えを作らせない

AIが辞書にない単語や、探索していない規則を返す可能性があります。そのため、AIの出力を必ず探索済みペアと照合してから表示します。AIは文章表現を担当し、単語ペアの成立判定はプログラムが担当します。

### 辞書と問題データを分離する

問題文を`index.html`にすべて直接書くのではなく、候補単語、探索結果、生成問題を分けています。これにより、単語を採用し直した場合でも同じ仕組みで新しい問題を作れます。

### 文字数・位置・規則の順でヒントを出す

いきなり答えを示さず、まず単語の長さ、次に変化した位置、最後に文字の変化内容を示します。小学生でも段階的に考えられるようにするための設計です。

### ブラウザだけでも確認できるようにする

APIキーがなくても自動生成で動くため、まず画面・辞書・規則探索・回答処理を確認できます。Gemini APIを設定した場合は、同じ探索結果を使って文章表現をAIに任せられます。

## 主なファイル

| ファイル | 役割 |
|---|---|
| `index.html` | 問題表示、候補選択、入力、ヒント、回答画面 |
| `app.py` | 単語探索、規則適用、編集距離判定、AI連携、HTTPサーバー |
| `unidic_candidates.js` | 画面に表示する12,600語の候補リスト |
| `generated_pairs.js` | 事前に生成した単語ペアの表示用データ |
| `rebuild_word_list.py` | UniDicから候補リストを再構築する補助スクリプト |

## 注意点

- AI生成にはGemini APIキーとインターネット接続が必要です。
- APIキーがない場合はAIではなく自動生成になります。
- 単語リストの「頻度順」は、一般の小学生の知名度順とは異なります。
- 辞書には意味や表記の揺れが残る場合があるため、候補一覧で最終確認できます。
- `app.py`を変更した場合は、起動中のサーバーを停止して再起動してください。
